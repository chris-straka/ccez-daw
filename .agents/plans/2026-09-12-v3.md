## Constraints And Non-goals

- Constraints: v0 + v1 contracts frozen (breaking change = new version + migration note, never silent drift); never hand-edit `ui/src/generated/*` (extend `core/src` + `bun run typegen`, confirm additive diff); `bun run check` green at every step; desktop-only (no Android/mobile job); sidecars optional — DAW runs fully without models.
- Non-goals for v3: new DAW features, new contracts versions, cloud/multiplayer, surround/Atmos, mobile targets, engine-side DSP export (stems + JSON only), round-robin pools, surround beds. Anything bigger than a polish fix becomes a v4 plan, not scope creep here.

## Key Decisions

1. **Release hardening first, pins second, polish last.** The `v0.0.0-test` tag is the milestone's heartbeat: signing + endpoints + a dry-run tag prove the pipeline before any other track lands. Model pins and UX fixes ride behind that gate.
2. **Three independent build tracks in separate new directories, parallel-safe.** Release work (CI/secrets/config), model-pin work (sidecar seam + docs), and polish work (UI fixes + game import) touch disjoint files; the only shared gate is `bun run check`.
3. **Pin models by decision, not by default.** Each sidecar gets an explicit verdict — a named local model (name, size, license) or a recorded "baselines only + HTTP seam" deferral. "Unpinned" stops being an option after v3.
4. **Close questions with game evidence.** The game's real states/params and engine import path get answered by actually importing one exported package into the user's game and hearing it — the v2 integration test, finally run for real.
5. **Ticket what we won't fix.** AU hosting-crate verdict, nih-plug fork choice, and any polish item that misses the tag become written follow-ups with owners, not silent gaps.
