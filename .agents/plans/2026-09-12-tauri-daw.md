## Goal

Build a fully featured desktop DAW ("ccez-daw") as a Tauri 2 app (Rust backend + SolidJS/TypeScript frontend), with native plugin support (CLAP + VST3 + AU), an MCP server, vim-style keybindings, and AI-assisted editing, executed by 28 agents across 14 tracks against frozen contracts. Architect for the full wishlist vision from day one (universal object model, one routing graph, any-to-any modulation, event-sourced project) while shipping a working v1 in slices. The user wants to learn how DAWs work as the build progresses.

## Success Criteria

- `bun run tauri:dev` launches the DAW shell with timeline, mixer, browser, piano roll, and command palette placeholders wired to real commands.
- TS bindings generated from Rust types in Track 0; `bun run check` fails if IPC/schema contracts drift.
- Rust audio engine plays a metronome + two clips through a graph with sample-accurate automation of volume/pan, via cpal output.
- At least one CLAP plugin loads sandboxed; killing it does not kill the session and state restores; VST3 and AU plugins load (AU on macOS).
- MIDI record/playback round-trips; piano roll creates/deletes/resizes notes with FL-style mouse behavior.
- Project saves instantly, reopens instantly, undo history survives restart, branches compare/merge.
- MCP server exposes project/track/clip/device/routing/automation tools; an MCP client can list tracks and add a clip.
- Every keybinding is remappable; vim motions work in arrangement/piano roll; command palette runs every action.
- Cross-target `cargo check` gates green on every push (macOS, Linux, Windows x64+ARM64); tag-driven multi-target release pipeline exists from week one.
- Each workstream ships a `docs/notes/<track>.md` DAW primer so the user learns the domain.

## Constraints And Non-goals

- Constraints: offline-first, no login, tiny idle footprint, Rust owns audio/project truth, frontend never blocks the audio thread, all AI output lands as editable undoable ops, framework code stays out of the DSP path (hot UI is canvas + rAF).
- Non-goals for v1: cloud/multiplayer collab, surround/Atmos, mobile targets, baked-in generative models (sidecar pattern only), business/licensing tiers. Phase-2 seams (not implementations): distributed DSP nodes, GPU acceleration, devices-to-WASM.

## Key Decisions

1. **Tauri 2 + Rust backend + SolidJS/TS frontend.** Solid signals map 1:1 onto param/automation thinking and compile to fine-grained real-DOM updates with no VDOM (per Solid README); Tauri is framework-free by architecture. Vanilla TS rejected (no shared conventions for an agent swarm); Leptos/WASM rejected (two Rust targets, slower iteration, zero UI perf gain since compute is native).
2. **Bun for all JS/TS work.** User constraint; corroborated by MCP SDK README (`bun add`, runs on Bun).
3. **Zod v4 for every schema boundary, generated from Rust.** Track 0 adds a typegen step: TS bindings derive from the Rust project/IPC types so contracts can't drift by hand-edit. MCP SDK tools use Standard Schema with Zod v4 as a first-class option.
4. **Universal object model from day one.** Clips, tracks, devices, modulators share one addressable node model — audio, MIDI, automation, and modulation are not separate type systems. v1 implements volume/pan/device params over it; the wishlist's anything-modulates-anything generalizes the same addressing.
5. **One routing graph** for audio, MIDI, modulation, and sidechains; the conventional mixer is a view over it.
6. **Audio I/O on cpal; plugins CLAP + VST3 + AU, sandboxed out-of-process**, with state snapshots for crash restore. nih-plug upstream is in maintenance mode → Track C evaluates the community fork first; AU hosting crates unevaluated (evidence gap, Track C week-one task); fallback is CLAP+VST3 first with AU following.
7. **MCP server as a separate Bun/TS package on the official SDK** (stdio + Streamable HTTP), tools mirroring the same action registry as palette, vim layer, scripting, and NL commands.
8. **Event-sourced project document (op log + snapshots), portable by design.** Instant autosave, infinite cross-session undo, Git-like branches; one package holds audio, presets, MIDI, automation, frozen plugin states for reproducibility.
9. **AI as background sidecars producing normal ops.** No model names pinned; nothing flattened, everything undoable.
10. **ccezstudio release pattern from week one.** Cross-target check gates on every push; strict-sequential tag-driven release (per-arch macOS dmgs, Windows NSIS x64+ARM64, Linux deb+AppImage on oldest supported base, updater signing, verify gate, auto-publish, prune), plus Linux audio dev libs and no Android (desktop-only v1).

## Recommended Approach

Track 0 freezes contracts first (repo layout, typegen pipeline, IPC table, project schema, op log, action registry, MCP tool list, release pipeline). Then 13 tracks build in parallel against those contracts with seam tests at each boundary, 28 agents total. Rust owns `core/` (project, engine, plugins, midi, audio); Solid owns `ui/`; `mcp/` bridges them. Every track ships a demoable vertical slice plus a DAW-primer note. Rejected: sequential build; in-process plugins; frontend-owned state; WASM frontend; hand-maintained TS types.

## Validation Plan

- Per track: its listed test plus `cargo test -p <crate>` or `bun run test --filter <pkg>`; all green required.
- Integration: `bun run tauri:dev` smoke (shell+engine+one plugin+MCP tool call); project round-trip (save/kill/reopen/undo); plugin-crash survival drill.
- Highest-risk validation: **Track C sandbox recovery + Track B glitch-free graph under load** — proven before editor polish.
- Release validation: check.yml green on every push; a `v0.0.0-test` tag produces all artifacts through the verify gate.

## Risks / Rollback

- nih-plug maintenance mode → fork evaluation in week one; fallback CLAP-only host, VST3 deferred.
- Solid-in-Tauri is a community (Vite-plugin) path, not a documented one → Track 0 proves dev/build cycle on day one; IPC boundary keeps a UI rewrite possible.
- AU hosting crates unevaluated → Track C evaluates in week one; fallback: macOS ships CLAP/VST3 first, AU follows behind a flag.
- AI model licensing/latency → sidecars optional; DAW runs fully without them.
- Rollback: feature flags per track; contracts versioned (`v0`); breaking change = new version + migration note; releases keep previous version as fallback (prune policy).
